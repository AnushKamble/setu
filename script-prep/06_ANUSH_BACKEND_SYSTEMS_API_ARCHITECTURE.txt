3. THE CANONICAL RAILWAY LEDGER (`models/railway.py`)
--------------------------------------------------------------------------------
The database schema standardizes all railway domain objects into relational tables:

1. `Section` Table (`sections`):
   - `id`: Unique section ID (e.g. `SEC-GZB-ALJN-UP`).
   - `name`, `division`, `track_type` (`UP_MAIN`, `DN_MAIN`), `length_km`, `max_speed_kmh`.
   - `adjacent_section_ids`: JSON array enabling 1-hop network delay propagation.

2. `Asset` Table (`assets`):
   - `id`: e.g. `AST-SEC-GZB-ALJN-UP-ENGINEERING`.
   - `section_id`, `department`, `asset_type`, `condition_score` (0.0 to 1.0), `criticality` (1 to 5).
   - `latent_degradation_factor`: Hidden ground-truth noise driving degradation without ML leakage.

3. `MaintenanceJob` Table (`maintenance_jobs`):
   - `id`: Canonical IR ID (e.g. `JOB-TMS-GZB-860`).
   - `asset_id`, `section_id`, `department` (ENGINEERING, TRD, S_AND_T).
   - `job_type`, `description`, `duration_p50_min`, `duration_p90_min`.
   - `priority_score` (LightGBM predicted [0, 1]), `cost_of_waiting` (hazard value).
   - `safety_class` (`CRITICAL`, `ISOLATION_REQUIRED`, `INTERLOCKED`, `HEAVY_EQUIPMENT`, `STANDARD`).
   - `statutory_deadline_minute`: Horizon minute by which work must start.
   - `status`: State machine (`BACKLOG` -> `PROPOSED` -> `COMMITTED` -> `IN_PROGRESS` -> `COMPLETED`).
   - `required_resources`: JSON dict of machinery and crew requirements.

4. `CorridorWindow` Table (`corridor_windows`):
   - Available time slots on the physical track between scheduled passenger trains.
   - `start_minute`, `end_minute`, `duration_min`, `traffic_impact_tier` (`NIGHT_OPTIMAL`, `OFF_PEAK`, `DAY_HEAVY`).

5. `TrainMovement` Table (`train_movements`):
   - Timetabled passenger and freight movements with entry/exit minutes and priority classes.


4. THE ZERO-TRUST INDEPENDENT SAFETY VALIDATOR (`validator/checker.py`)
--------------------------------------------------------------------------------
Reference Document: `00-SIX-DAY-MASTER-PLAN.md` Part 1 #12 & `DECISIONS.md` Decision 003

This is SETU's premier safety defense against software bugs, adversarial corruption,
or solver misconfigurations.

WHAT IS ZERO-TRUST VALIDATION?
  - The solver's own internal constraints are NEVER blindly trusted.
  - Before any schedule can be sent to the frontend or exported to BDMS, it is passed
    to `IndependentValidator.validate()`.
  - The validator is completely decoupled from OR-Tools and executes 7 exhaustive checks:

  CHECK 1: Duplicate Job Assignments
    - Asserts that no job is scheduled in two different windows or executed more than once.

  CHECK 2: Window Duration Capacity with P90 Buffers
    - Sums the P90 durations of all jobs assigned to a window, subtracts shared convoy
      savings, and verifies that the total required time <= window duration.

  CHECK 3: Pairwise Cross-Department Safety Compatibility
    - Evaluates all pairs of jobs (j_a, j_b) in the block against `is_safety_compatible(j_a, j_b)`.
    - Detects illegal combinations (e.g. Ballast Cleaning Machine + Track Tamping on same section).

  CHECK 4: Section Exclusivity & Contiguous Block Encroachment
    - Confirms that every job in the block belongs to the exact physical section of the window.

  CHECK 5: Train Timetable Passenger Express Clash Detection
    - Cross-references the block window [start_minute, end_minute] against all express
      train timetables (Rajdhani, Shatabdi, Vande Bharat).
    - Proves zero temporal overlap with protected train paths.

  CHECK 6: Mandatory Statutory Inspection Deadlines
    - Verifies that every statutory safety job (e.g. USFD rail fracture) has its assigned
      start minute <= statutory_deadline_minute.

  CHECK 7: Department Resource Pool & Equipment Limits
    - Asserts that total simultaneous crew demand <= division headcount, and simultaneous
      Tower Wagon requests <= depot inventory.

If any check fails, the plan is flagged with a detailed `ValidationViolation` report.
Tested against deliberate adversarial corruptions in `tests/test_validator.py`.
